# 校招岗位雷达 · Campus Job Radar

> **校招 / 秋招 / 春招 / 实习岗位聚合监控**：自动盯着上千家公司的招聘官网和招聘公告，一有新岗位就告诉你。
> 拉下来自带 **22444 个岗位、12488 家公司**，不用先学爬虫；本地一键启动，数据只存你自己电脑。

**解决的痛点**：校招、秋招、春招、实习的招聘公告发布得很零散。你不知道哪家公司今天开了新批次，只能反复刷自己记得的那几个官网，或者靠群里、短视频里的截图。这个工具把这些事自动化：每天定时去官网看一遍，把"新增了什么岗位"整理成一张清单给你。

适合这些人：正在找**校招 / 秋招 / 春招 / 实习**的在校生和应届生、想一次盯住几百家公司招聘动态的求职群、需要把分散在各官网的**招聘信息聚合**到一张表里的任何人。纯本地运行，不依赖任何线上服务。

## 第 4 步：看懂工作台

左侧是导航。当前主页面是「岗位变化」，它已经把原来的「每日新增」并了进来：

> **页面合并说明**：以前是「今日新发布」+「每日新增」两个页签，现在合成一个「岗位变化」。
> 上半部分是筛选条（关键词 / 方向 / 城市 / 类型 / 时间窗口 / 订阅），下半部分是指标卡和按公司分组的变化列表；
> 筛选条件直接作用于这个列表，指标卡跟着一起变。「全部岗位」仍是独立页签（它回答的是"库里有什么"，不是"今天变了什么"）；
> 「智能推荐」暂时从界面隐藏，代码和接口都还在。

### ⓪ 手动采集（先把数据拉进来）

「今日新发布」里的数据来自采集：**你不开采集，它就不会自己更新**。想把每天的校招/实习动态拉进来，有两种方式：

- **手动（推荐新手）**：打开「今日新发布」页，右上角就有「采集最新岗位」按钮，点一下就开始采集。按钮旁边显示实时进度和上次采集时间（服务重启后依然记得）
  - 想改范围就展开下面的「手动采集」面板：勾行业范围 + 招聘类型（实习 / 秋招 / 春招）+ 时间窗口（近 1 / 3 / 7 / 30 天）
  - 不展开也没关系：按钮按上次保存的范围采集
  - 源站按发布时间倒序，采集翻到窗口边界就停，所以**近 7 天通常几秒到几十秒**，不再全量扫 2 万条
  - **「材料/新材料」是细筛项**：源站没有独立的材料分组，材料岗散在化工/制造/半导体/汽车四个行业里，所以勾它会先限这四个行业、再按岗位名筛出材料相关岗位（材料、高分子、电池、冶金、封装、硅片……）。它不会把四个行业的 HR、财务、销售一起收进来，也不影响你另外勾的普通行业。
  - **工作地点**：填「郑州」就只收郑州的岗位（「郑州市」「郑州航空港区」也算），留空是全国。可以写多个城市，用顿号或逗号分隔。城市按源站公告里的工作地点匹配，一家公司列了 20 个城市时，只要其中一个是你填的城市就算命中。
  - **届别**：选「2027 届」时，秋招/春招只收写明 2027 届的公告；**实习不受届别限制**——寒假实习、日常实习、明年春季实习经常不写届别，卡届别会把它们全删掉。
  - **「同时按岗位名判断方向」（默认开）**：行业范围优先看公司的行业标签，但很多公司被标签归到了别的行业——郑州商品交易所标的是「金融」，可它招软件研发岗；许昌继电器标的是「制造」，可它招嵌入式开发。勾上这一项，岗位名对得上也算，取消就严格只看公司行业。
- **双击「一键采集.bat」**：三步选择题，不用记参数（见上面的「懒人版」）
- **命令行脚本（想放到批处理/定时任务，或用细粒度参数）**：见下面「⓪-B」
- **自动（可选）**：跑一次 `scripts/install_windows_tasks.ps1`，之后每天定时采集，不用手动点

范围会记住：选过的行业范围保存下来，下次打开还是你的选择。已经入库的岗位不受缩小范围的影响。

> **采完显示「新增 0 · 变更 0」不要以为坏了。** 它只说明两次采集之间**没有企业发新公告**——一天点几次，中间没新公告就是 0。判断采集真的跑了，看后面的「拉取 X 条 · 范围内 X 条」：有数字就说明源站访问和行业过滤都正常。「今日新发布」上那个「新发布 XXXX」是所选时间窗口（24 小时 / 3 天 / 7 天）里累计的新增，不是这一次采集的成果。

### ⓪-B 用脚本采集：最近 24 小时 / 7 天，只看材料类或计算机类

「一键采集.bat」背后就是这个脚本（`scripts/easy_collect.py` 负责问问题，这里负责干活）。
要放到定时任务/批处理里，或者想用 `--since`、`--groups`、`--dry-run` 这类细粒度控制，直接用命令行：

```powershell
# 最近 7 天，计算机类 + 材料类（默认）
python scripts\collect_recent.py

# 最近 24 小时
python scripts\collect_recent.py --days 1

# 只要材料类，最近 30 天
python scripts\collect_recent.py --preset materials --days 30

# 只要计算机类，并额外限定关键词
python scripts\collect_recent.py --preset cs --days 7 --keywords 算法,后端,嵌入式

# 只看郑州，2027 届秋招 + 各类实习，最近 90 天
python scripts\collect_recent.py --days 90 --groups internet-tech,materials --city 郑州 --cohort 2027

# 先看会采到什么，不写库
python scripts\collect_recent.py --days 7 --dry-run
```

参数说明：

| 参数 | 作用 |
| --- | --- |
| `--days N` | 最近 N 个自然日（含今天），默认 7 |
| `--hours N` | 最近 N 小时，和 `--days` 二选一 |
| `--since / --until` | 指定起止日期，如 `--since 2026-10-28 --until 2026-11-04` |
| `--preset cs / materials / both` | 领域预设：计算机类 / 材料类 / 两者（默认 both） |
| `--keywords` | 追加关键词（逗号分隔）；给了就按关键词匹配岗位名 |
| `--groups` | 按行业组选（`internet-tech`、`materials`、`energy-chemical-environment` 等）；给了就**不再叠加**预设关键词 |
| `--city` / `--cities` | 只看这些城市的岗位：`--city 郑州` 或 `--city 郑州,洛阳`（默认全国） |
| `--cohort` | 只看某届校招，如 `--cohort 2027`；0＝不限。**实习不受此限**，寒假/日常/春季实习都会收 |
| `--role-match` / `--no-role-match` | 是否同时按岗位名判断方向（默认跟随网页里的开关，开）。关掉就严格只按公司行业标签 |
| `--list-companies` | 只按公司分组列出会采到什么，不写库；看完再用 `--only-companies` 挑 |
| `--only-companies` | 只入库这些公司（逗号分隔，按公司名包含匹配），其余丢弃 |
| `--types` | 招聘类型：`实习` `秋招` `春招`（可多选） |
| `--dry-run` | 只统计和预览，不写库 |

**匹配口径**：只看岗位名称（`positionsText`），不看公司名和行业标签——互联网公司也在招设计师和 HR，那些不算「计算机类」。所以宁可少收，也不塞噪声。想放宽就加 `--groups`。

> `--groups materials` 和网页上勾「材料/新材料」是同一套规则（同一份代码、同一份关键词），区别只是脚本还要求发布时间落在你指定的窗口内。

跑完会打印时间窗、拉取条数、命中条数、新增/更新条数，以及每条新岗位的**发布日、截止日**：

```text
时间窗：最近 7 天（2026-10-29 ~ 2026-11-04）
范围：计算机类 + 材料类（0 个行业组 + 68 个关键词）
拉取 350 条 · 窗口内 218 条 · 命中 94 条（行业 0 / 关键词扩展 94）
```

### ⓪-C 不只 OfferBiu：直采企业官网 / 导入外部岗位

上面的按钮和脚本读的是 OfferBiu（一个校招公告聚合站）。它是很好的底座，但只有它一个来源，
就意味着"它没收的公告，你这里也没有"。所以有两条补充通道：

**A. 直采企业招聘系统**（自动，推荐）

```text
# 看看哪些公司能直采
python scripts\crawl_company_sites.py --list

# 抓这两家（已内置，河南本地）
python scripts\crawl_company_sites.py --company shuanghui,cmoc

# 所有已接入的公司
python scripts\crawl_company_sites.py --connected
```

支持四类主流招聘系统，加公司只需在 `config/companies.yaml` 里写一行域名：

| 招聘页长这样 | crawler | 说明 |
| --- | --- | --- |
| `xxx.zhiye.com` | `beisen` | 北森，大厂/国企常见 |
| `wecruit.hotjob.cn/SUxxxx/...` | `hotjob` | 北森热招门户 |
| `app.mokahr.com/campus-recruitment/xxx/12345` | `moka` | Moka |
| `xxx.jobs.feishu.cn/campus` | `feishu` | 飞书招聘 |

脚本只收**校招/实习**：官网热招里的"电气维修工"这类社招岗会被跳过（`--all` 可强制全收），
岗位标题里的"27 届"会写进届别。

**B. 导入外部岗位**（任何来源，手工/半自动）

高校就业网、集团公告、别的聚合站——只要整理成 JSON/CSV 就能进来，**每条必须带 URL**：

```text
python scripts\import_jobs.py --file .data/incoming/zz.json --dry-run   # 先预览
python scripts\import_jobs.py --file .data/incoming/zz.json             # 再入库
```

```json
{
  "source": "company-site",
  "items": [
    {"company": "郑州商品交易所", "title": "软件研发岗", "city": "郑州",
     "url": "https://www.czce.com.cn/...", "published_at": "2026-11-01",
     "deadline": "2026-11-20", "track": "campus", "cohort": 2027}
  ]
}
```

入库后在「全部岗位」里能看到来源标签：`招聘公告`（OfferBiu）/ `官网直采`（企业系统）/ `外部来源`。

**哪些站点能自动爬、哪些不能**（2026-11 实测）：

| 来源 | 状态 |
| --- | --- |
| OfferBiu 公开接口 | ✅ 直接可用 |
| 北森 / hotjob / Moka / 飞书 招聘页 | ✅ 可用（需知道公司域名） |
| 高校就业网（郑大等） | ⚠️ 列表页是 JS 渲染，要逆向接口 |
| BOSS 直聘 / 智联 / 51job / 职友集 | ❌ 登录 + 反爬，不做 |

### ① 岗位变化

- 顶部四个数字：新发布 / 内容变更 / 已下架 / 有变化的企业
- 下面按公司分组，每条前面有「新增」「变更」「下架」标签
- **点岗位名**直接跳官网原页，可以立刻投
- 筛选条：关键词 / 方向 / 城市 / 校招实习 / 今天·3 天·7 天·30 天；留空就是看全部
- 填好条件点「按条件筛选」，指标卡和下面的公司列表会一起收窄；点「清空筛选」回到全部
- 想长期盯同一组条件：填个订阅名称 →「保存为订阅」，以后点那枚胶囊就一键套用

> **公司名旁边的小标签**：`民营 / 国资 / 外资` 是企业性质，`3,105 人` 是员工规模。
> 规模只显示**能核对到出处**的（年报、东方财富 F10 披露），鼠标悬停能看到「截至什么时候、来自哪里」；
> 查不到就完全不显示——不会写「未知」，更不会猜一个数字。
>
> **每条岗位都会标出「发布 11-04 · 截止 11-30（剩 26 天）」**，三个页面口径一致：
>
> | 字段 | 怎么来的 | 没有的时候 |
> | --- | --- | --- |
> | 发布 | 招聘公告的源站收录日，**精确到天** | 显示「未公布」 |
> | 截止投递 | 公告原文的截止日期 | 公告没写日期、只写「尽快投递」就照录原文；什么都没写显示「未公布」 |
>
> 剩余 ≤3 天标黄，已过期划掉。工具**不会猜日期**：源站只给到天，就不编造时分；公告没说，就不写一个看起来像真的截止日。
>
> **一个边界**：发布时间是从「支持标注日期」之后的采集开始记录的（2026-11-04 起），更早入库的老岗位没有可回溯的来源，
> 会一直显示「未公布」——这是有意的，不给历史数据编日期。需要的话可以重新采一次覆盖它们。

> 第一次用可能显示「还没有岗位变化记录」，这正常：第一次采集只是把现存岗位记成「底账」，第二天起才记录真正的「新增」。

### ② 全部岗位

- 所有已收录的岗位（不只是今天新增的）
- 可筛选：校招 / 实习、招聘公告 / 官网采集
- 搜索框能搜公司名、岗位名、城市

### ③ 实习岗位

- 专门看实习岗，包含「这个实习要求什么条件」「你差在哪」
- 上传简历后才有匹配分数（可选，不上传也能看岗位）

### ④ 智能推荐（暂时关闭）

> 入口已隐藏（`INTEL_ENABLED_TABS` 加上 `"recommend"` 即可恢复）。下面描述保留给恢复后的用法。

「岗位变化」页顶部原来的标签：**岗位变化 / 全部岗位 / 智能推荐**。

点「智能推荐」，第一次会提示没有偏好信息。展开下面那行「没有模型密钥？把简历内容粘贴到这里」：

1. 把简历里的**教育背景、技能、项目、实习经历**粘进文本框（不用上传文件）；
2. 点「提取关键词」——这一步**不联网、不需要 API Key**，只用本地词表识别；
3. 看看识别出的方向、技能对不对，点「保存并推荐」；
4. 下面立刻按匹配度排出岗位，每条会写明加分原因，比如 `方向命中 大模型/智能体 +35`。

打分的四个维度（总分 100）：方向匹配 35 + 关键词匹配 30 + 技能匹配 20 + 招聘类型 15。分数用来**排序**，不是录用概率。

> 也可以在「配置」页上传 PDF/Word 简历做更细的解析，但那一步需要配置 DeepSeek API Key。没有 Key 就用上面粘贴的方式，效果对排序够用。

### ⑤ 每日新增 → 已并入「岗位变化」

这个页签没有了：筛选条已经搬到「岗位变化」页，回答的还是同一个问题——"**今天新出现了哪些岗位，且符合我的条件**"。

用法：

- **偶尔看一次**：填关键词 / 方向 / 城市 / 类型，点「按条件筛选」，指标卡和公司列表一起收窄；点「清空筛选」回到全部；
- **长期关注**：同样填好条件，再填个订阅名称（比如"大模型实习-北京"），点「保存为订阅」。以后点顶部那颗胶囊就自动套用。

时间窗口在筛选条右侧，默认「今天新增」，可切「最近 3 天 / 7 天 / 30 天」。

筛选条下方会显示「当前显示：全部变化 / 当前筛选：关键词「算法」……」和「数据最后更新」——**筛选本身不用等（毫秒级）**，真正要等的是采集任务。如果显示几小时前，说明该采了，不是该等筛选。

小提示：填「算法」会顺带匹配「机器学习」「深度学习」这类写法，否则标题写「Agent 研发」的岗位永远搜不到。靠近义词命中的会标注「关键词近义」，排在精确命中的后面。

### ⑥ 岗位画像（想投之前先看清这个岗）

入口在各岗位列表里（「27届校招」「实习岗位」），每行最右边有「分析 / 画像」按钮。**点哪条就分析哪条**，不会预先算全库。

展开后你会看到：

| 内容 | 例子 |
| --- | --- |
| 薪资 | 「公告未披露」或「15-20万」（只转述公告原文） |
| 门槛 | 学历本科、要求 2 年自动化测试经验，每条都附上公告原句 |
| 相对位置 | 该公司在库 52 个岗位，同方向 0 个，合肥占 31 个 |
| 判定 | 要求偏高 / 中等 / 较低 / 信息不足，下面是逐条依据 |
| 模型解读 | 2~3 句人话（配了 API Key 才有） |

**先说清三个真实数字**，免得你以为它坏掉了：

| 项目 | 能查到的比例 |
| --- | --- |
| 公告里写了薪资 | **约 0.4%**（绝大多数招聘公告不写钱） |
| 公告里写了学历/院校/经验 | **约 7%** |
| 同公司同方向岗位统计 | 100%（本地库算的） |

所以多数岗位点开是「薪资未披露 + 门槛信息不足」，但**相对位置和解读仍然有效**——"这家公司这个方向只放了 1 个岗"本身就是有用信息。

**为什么不给"往年录了什么学生"**：没有公开数据能支持这种结论。工具只报公告写明的条件，并且明确标注这是"公告门槛"不是"实际录取水平"。

### ⑦ 「高匹配」为什么是 0（不是坏了）

「27届校招」页那个「高匹配 0」不是 bug，是新库还没评过分。评分要三个条件同时成立：

1. 岗位有真正的 JD 正文（公告级岗位大多只有岗位名列表）
2. 岗位标题命中你简历里的目标方向（否则判「方向不符」，直接不给分）
3. 配置页的模型密钥 + 岗位评分开关都打开

想让它出数字，跑这一条（不重爬，只补评分）：

```bash
python scripts/score_pending.py --dry-run      # 先看有多少条能评
python scripts/score_pending.py --concurrency 4
python scripts/score_pending.py --rescore       # 换过简历后，先清旧分再重评
```

**关键**：评分里的「项目证据」占 25 分，只能从上传简历解析出来。只粘关键词的话分数会卡在 60 出头——实测同一条岗位，画像里没有项目证据是 64 分，把你简历里的项目写进去是 86 分。

**高匹配多少取决于你的画像写多宽**：画像只写"大模型"，硬件、结构、测试岗会全部被过滤掉。22444 条里，官网采集的 135 条中标题能命中方向的只有 61 条。

### ⑧ 公司名旁边的「民营 / 国资 / 外资」

「岗位变化」「全部岗位」里公司名后面有小标签：性质（民营/国资/外资）和员工规模（如 `3,105 人`）。它来自招聘公告自带的性质字段（覆盖约 44%），没有的用 `config/company_nature.yaml` 补——那是个纯文本文件，你不同意哪家直接改，刷新页面就生效。

只做粗分类是有意的：混合所有制、国资参股但民营团队经营的公司，不同口径答案不同，标太细反而更容易错。

另外「公司」页只列**已接入官网采集**的几十家，不是全部 6553 家——后者的公司在「全部岗位」里按公司名搜索。两个页面口径不同，不是数据丢了。

## 第 5 步：让它每天自动更新（可选）

不做也能用，只是岗位清单不会自己变新。

### Windows

在项目文件夹里打开 PowerShell：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install_windows_tasks.ps1 -DryRun
```

这一步**只是预览**，会列出将要创建的 6 个计划任务，不会真的创建。确认后去掉 `-DryRun` 再跑一次：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install_windows_tasks.ps1
```

之后每天自动执行：

| 时间 | 做什么 |
| --- | --- |
| 08:00 | 抓配置企业的官网岗位 |
| 08:15 | 检查爬虫是否正常 |
| 08:30 | 同步最新招聘公告（数量最多） |
| 09:00 | 同步招聘邮箱（不用可不配） |
| 09:30 | 把新岗位推到群里（需先做第 6 步） |
| 20:00 | 复核投递进度（不用可不配） |

想取消：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\uninstall_windows_tasks.ps1
```


粘贴下面几行（路径换成你的），保存退出：

## 第 6 步：推送到微信/QQ 群（可选）

宿舍群、班级群一起用：每天 09:30 自动发「今天哪些公司放岗了」。

### 1. 拿一个群机器人地址

| 群类型 | 怎么拿地址 |
| --- | --- |
| 企业微信群 | 群右上角 → 群机器人 → 添加机器人 → 复制 Webhook 地址 |
| 钉钉群 | 群设置 → 智能群助手 → 添加机器人 → 自定义 → 复制 Webhook |
| 飞书群 | 群设置 → 群机器人 → 添加机器人 → 自定义机器人 → 复制地址 |
| QQ 群 | 需自建转发服务（OneBot 等），地址填到 `generic` 类型 |

### 2. 填配置

打开 `config` 文件夹，把 `notify.example.yaml` **复制一份改名**为 `notify.yaml`，用记事本打开填地址：

```yaml
webhooks:
  - name: 宿舍求职群
    type: wecom
    url: https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=你的KEY

digest:
  hours: 24
  max_items_per_push: 8
```

`type` 填 `wecom`（企业微信）/ `dingtalk`（钉钉）/ `feishu`（飞书）/ `generic`（通用）。
钉钉、飞书如果开了加签，再加一行 `secret: 你的密钥`。

### 3. 先预览再发送

```powershell
python scripts\intelligence_digest.py
```

屏幕上会打印「将要发送的内容」。确认后加 `--push` 真发：

```powershell
python scripts\intelligence_digest.py --push
```

## 常见问题（照着做就行）

### 1. 提示「'python' 不是内部或外部命令」

装 Python 时没勾 `Add python.exe to PATH`。最省事：卸载重装，**记得勾那个框**。

### 2. PowerShell 提示「无法加载文件 Activate.ps1，因为在此系统上禁止运行脚本」

先运行这行，再重做第 3 步：

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

### 3. `pip install` 特别慢或卡住

命令里已经带了清华源。还慢就换阿里源：

```powershell
pip install -e ".[dev]" -i https://mirrors.aliyun.com/pypi/simple/
```

### 4. 页面中文乱码

在 PowerShell 里先运行 `chcp 65001` 再启动。

### 5. 提示端口 8010 被占用

换个端口：

```powershell
python scripts\quickstart.py --port 8020
```

然后访问 <http://127.0.0.1:8020/?view=intelligence>。

### 6. 页面能开，但「岗位变化」是空的

正常。第一次采集只建「底账」，不算新发布。想立刻有内容：

- 点「全部岗位」看已有的 2 万多个岗位；
- 或等第二天定时任务跑完再看。

### 7. 想立刻看最新岗位，不想等定时任务

打开「今日新发布」页 → 顶部「手动采集」面板 → 选范围 → 点「开始采集」，采完自动刷新。

也想在命令行跑：`python scripts\collect_offerbiu.py --types 实习 秋招 春招`（`--max-pages` 要给足，秋招有一万三千多条，默认给 300）。

### 8. 只想要互联网岗位，不想要律所、医院、学校

手动采集面板里只勾你要的行业（比如「互联网/软件/AI」「半导体/电子硬件」），范围外的公告直接不入库。

已经入库的岗位可以用「全部岗位」的搜索框临时筛。

> 注意：缩小范围只是不再往里加，原来已经进库的岗位不会被删。

### 9. 采集跑完了，但一条新岗位都没有

先别怀疑它坏了，按下面三条自查：

1. 看采集面板里的**「拉取 X 条 · 范围内 X 条」**。有数字 = 源站访问和行业过滤都正常，问题只是没有新东西。
2. 「新增」是**增量**：库里已经有的岗位不会重复计数。今天连着采两次，中间没有新公告，第二次必然是 0。
3. 「今日新发布」的「新发布 XXXX」是所选窗口（24 小时 / 3 天 / 7 天）内累计的新增事件，可能来自昨天那次采集，和刚才这次无关。

真实节奏参考：10 月底实测，一天内上午、下午各采一次，上午那次新增 9 条岗位 + 8 家新企业，下午那次就是 0——因为数据源在两小时内确实没发新公告。**新增要等企业真发公告**，秋招补录和春招预告从 11 月起会明显变多。一天采 1~2 次就够，采再频繁也不会凭空多出岗位。

### 9-B. 点了「采集最新岗位」，一直转圈怎么办

先看按钮旁边的状态文字：

- 显示「正在拉取秋招公告：第 3/12 页（已取 150 条）· 已运行 8 秒」= 正常，等它跑完；
- 显示「已运行 5 分钟以上」= 窗口可能开得太大。展开「手动采集」面板，把时间窗口从「近 30 天」调成「近 7 天」，再点一次；
- 显示「请求超过 45 秒没有响应」= 前后端已经断开，刷新页面重试即可（旧版本会永远转圈，这一版会给明确提示）。

如果按钮一直停在「采集中…」，先确认服务还在跑：浏览器打开 <http://127.0.0.1:8010/api/intelligence/collect/status>，返回 JSON 就说明后端正常，刷新页面即可恢复。

### 10. 数据存在哪？会上传到网上吗？

全部存在你电脑上的项目文件夹（`.data` 目录里的数据库），**不上传任何服务器**。想清空：停服务 → 删 `.data` 文件夹 → 重跑 `quickstart.py`。

### 11. 双击那两个文件，弹出一串英文 / 没反应

按提示对号入座：

| 看到什么 | 什么意思 | 怎么办 |
| --- | --- | --- |
| `[X] Python not found on this computer` | 电脑上没装 Python，或装的时候没勾 PATH | 回到[第 0 步](#第-0-步装-python只需一次)装一次 |
| `[!] The Python environment is not ready yet` | 还没做首次安装 | 先双击「一键启动.bat」，等它装完（几分钟），再回来双击采集 |
| `工作台已经在运行` | 网站本来就开着 | 直接用浏览器打开它给的地址，不用再启一个 |
| `端口 8010 被别的程序占用了` | 别的软件占了 8010 | 按提示换端口，例如 `python scripts\quickstart.py --port 8020` |
| 窗口一闪就没了 | 说明脚本执行完立刻退出（不正常） | 在文件夹空白处 Shift+右键 →「在此处打开 PowerShell」，输入 `.\一键启动.bat` 回车，就能看到完整报错 |

### 12. 选了行业和城市，怎么只采到几十家公司？

这是数据本身的样子，不是采集失败。用「互联网/软件/AI + 材料/新材料 · 郑州、洛阳 · 2027 届」实测（2026-11-05）：

| 筛选层 | 近 30 天 | 近 90 天 |
| --- | --- | --- |
| 数据源在这段时间发布的公告 | 1,250 条 | 8,600 条 |
| 其中工作地点含郑州/洛阳 | 57 条 | 380 条 |
| 再筛 2027 届（实习豁免） | 45 条 | 317 条 |
| 再筛互联网/材料行业 | 10 条 / 10 家 | 80 条 / 79 家 |
| **加上「按岗位名判断方向」** | **22 条 / 21 家** | **153 条 / 147 家** |

三个原因：

1. **30 天太短**。2027 秋招公告大多在 8–9 月发布，最近 30 天只覆盖补录和零星新开的批次。想筛 2027 秋招，建议选 **90 天**（翻页会久一点，约 1–2 分钟）。
2. **郑州、洛阳的公告本来就少**。OfferBiu 是全国聚合，一个月里郑州+洛阳全行业只有 57 条，互联网/材料公司占其中一小部分。
3. **行业标签是"公司行业"，不是"岗位方向"**。郑州商品交易所=金融、许昌继电器=制造，但它们都在招开发。默认开启的「按岗位名判断方向」就是为了把这类岗位捞回来；关掉就会明显变少。

删掉整个项目文件夹即可，不留系统级残留。

## 进阶用法（不写代码也能做）

### A. 增删要监控的公司

打开 `config/companies.yaml`（没有就把 `companies.example.yaml` 复制改名），每家公司一段：

```yaml
  - id: tencent
    name: 腾讯
    careers_url: https://join.qq.com/
    crawler: tencent
    integration_status: connected
```

- `integration_status` 写 `connected` 才会抓，写 `pending_verification` 只登记不抓
- 不想要哪家，把 `connected` 改成 `pending_verification`
- 想加新公司，复制一段，改 `id`、`name`、`careers_url`、`crawler`

**`crawler` 怎么选？看招聘页网址就知道：**

| 招聘页长得像 | 填什么 |
| --- | --- |
| `xxx.zhiye.com` | `beisen` |
| `xxx.hotjob.cn` | `hotjob` |
| `app.mokahr.com/campus-recruitment/xxx` | `moka` |
| `xxx.jobs.feishu.cn` | `feishu` |
| 其他（打开空白、要等几秒才出内容） | `render` |

### B. 多拉一些岗位

```powershell
# 实习全量
python scripts\collect_offerbiu.py --types 实习 --max-pages 60

# 秋招 + 春招
python scripts\collect_offerbiu.py --types 秋招 春招 --max-pages 150
```

### C. 补公司人数规模

页面上的员工数来自两份数据，按可信度排序：

| 文件 | 覆盖 | 说明 |
| --- | --- | --- |
| `config/company_size.yaml` | 几十家（人工） | 逐条核对过年报，带出处和截止时间；**冲突时以它为准** |
| `config/company_size_listed.json` | 约 1.3 万家（自动） | 从东方财富 F10 抓的上市公司最新披露员工数 |

想手工补一家，往 `company_size.yaml` 里加：

```yaml
companies:
  某某科技:
    aliases: [某某]          # 可选：别名、英文名、简称
    employees: 5200
    as_of: "2024年末"        # 数据截止时间
    source: "2024 年年度报告"  # 出处，必填
```

想刷新自动那一层（建议隔几个月跑一次）：

```text
python scripts\fetch_company_size.py --dry-run   # 先看覆盖率
python scripts\fetch_company_size.py             # 写入 config/company_size_listed.json
```

> 匹配规则是**精确匹配**：会把「股份有限公司 / 有限公司」这类工商后缀剥掉，再比对公司名；
> 但**不会**剥掉「集团 / 控股 / 股份」——「中国稀土集团」和上市公司「中国稀土」是两家主体，
> 宁可匹配不上，也不能把集团的岗位标成子公司的人数。

### D. 更新打包的数据（分享给别人的时候）

```powershell
python scripts\export_seed.py
```

会重新生成 `data/seed/jobs.jsonl.gz`，提交到 GitHub 后，别人拉下来就自带最新岗位。

## 技术说明（给开发者）

<details>
<summary>点展开</summary>

### 架构

- **采集层**：Requests / Playwright / BeautifulSoup，79 个站点适配器（57 个真实实现，18 个占位）
- **应用层**：FastAPI + 原生 HTML/CSS/JS（无前端构建）
- **情报层**：`packages/intelligence/` —— 事件写入、日报聚合、群机器人推送、多源岗位导入（OfferBiu / 官网直采 / 外部 JSON）
- **调度层**：本地任务调度器 + Windows 计划任务 / cron，6 个固定任务
- **数据层**：SQLAlchemy 2.0，SQLite（默认）/ PostgreSQL 16，迁移在 `migrations/`

### 数据流

```
OfferBiu 公告 / 企业招聘系统 / 外部导入（JSON、CSV）
        ↓  定时任务或手动脚本
   job_snapshots（岗位快照）
        ↓  与上一轮对比
   job_events（新增/变更/下架事件）
        ↓
   工作台「今日新发布」 + 群机器人日报
```

设计约定：

- **基线机制**：每家公司第一次采集只记底账，不产生大量「新发布」噪音
- **事件与采集解耦**：事件写失败不影响已提交的岗位数据
- **口径分离**：`cohort` 未知的岗位照样入库、照样进「今日新发布」，只是不进上游严格的「27 届校招」视图

### 主要脚本

| 脚本 | 用途 |
| --- | --- |
| `scripts/quickstart.py` | 一键：准备配置 + 导入种子 + 启动 |
| `scripts/collect_offerbiu.py` | 拉招聘公告（`--dry-run` 只统计） |
| `scripts/collect_recent.py` | 只采最近 N 天 / N 小时的岗位，可按计算机类 / 材料类过滤，自动入库 |
| `scripts/easy_collect.py` | 上面那个脚本的问答版，供「一键采集」双击入口调用（`--defaults` 可无交互跑） |
| `scripts/backfill_application_window.py` | 给历史岗位补「截止投递时间」（老库升级后用一次） |
| `scripts/fetch_company_size.py` | 抓上市公司员工数写入 `config/company_size_listed.json`（公司规模标签的数据源） |
| `scripts/export_seed.py` / `import_seed.py` | 导出 / 导入岗位快照 |
| `scripts/intelligence_digest.py` | 预览或推送日报（`--push` 真发） |
| `scripts/run_local_task.py` | 手动触发某个定时任务 |
| `scripts/install_windows_tasks.ps1` | 注册 Windows 计划任务 |

### API

| 端点 | 用途 |
| --- | --- |
| `GET /api/intelligence/digest?hours=24&track=internship` | 按企业分组的变化汇总 |
| `GET /api/intelligence/events?event_type=new` | 扁平事件流 |
| `GET /api/intelligence/jobs?track=campus&page=1` | 分页浏览全部岗位 |
| `GET /api/intelligence/coverage` | 已入库 / 在招 / 校招口径统计 |
| `GET /api/intelligence/push-preview` | 渲染将要推送的原文 |
| `POST /api/intelligence/collect` | 手动触发一次采集：`{"industry_groups": [...], "recruit_types": [...], "days": 7}` |
| `GET /api/intelligence/collect/status` | 采集进度 / 上次结果（服务重启后仍可见） |

岗位相关接口都返回 `publish_date` / `deadline_date` / `deadline_text`，空字符串表示源站没写（UI 显示「未公布」）。

## 合规与数据

- 只访问公开可访问的招聘页面，默认低频（每天 1~2 次），不绕过登录 / 验证码 / robots 限制。
- 打包的数据只含**元数据**（公司、岗位名、城市、届别、截止时间、投递链接），**不含 JD 正文**。投递时点链接去官网看原文。
- 数据只存本机，不上传任何服务器。
- 对外提供服务前请自行确认站点条款并加鉴权。
